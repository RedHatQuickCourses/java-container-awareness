Welcome to our module on Introduction to Containerized Java. In this session, we will focus on the evolution of the Java Virtual Machine, or JVM, and how it has been designed to operate effectively within container environments. Understanding these concepts is essential for deployments in orchestrators such as OpenShift and Kubernetes.

Currently, Java runtimes utilize container awareness to detect cgroup limits. This allows the JVM to automatically adjust its resource consumption based on container boundaries, rather than relying on the limits of the host hardware.

There are four key aspects to this evolution that you should keep in mind:

First is the evolution of Java itself, which has shifted from host-based resource perception to environment-aware detection. 

Second is the concept of container awareness, which is the ability of the JVM to recognize and respect the specific memory and CPU limits imposed by the container runtime.

Third, we look at cgroup detection. This involves leveraging kernel-level control groups to monitor and manage resource availability accurately.

Finally, there is operational efficiency. By ensuring the JVM aligns its internal memory and thread management with defined container resource limits, we can significantly simplify our deployments.

This course is based on the current OpenJDK implementation. For further reading, I encourage you to consult the article titled "How to use Java container awareness in OpenShift 4," which is available on the Red Hat Developers website.
