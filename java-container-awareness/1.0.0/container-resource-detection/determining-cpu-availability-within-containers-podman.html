Hands-on Exercise: Inspecting CPU Awareness in a Local Podman Environment

This hands-on exercise demonstrates how to deploy and verify Java’s container CPU awareness using s2i toolkit with Podman, following the guide build OpenJDK container images locally using the standalone S2I tool.

  1. Run the following commands to install s2i toolkit on the bastion VM:

    curl -LO https://github.com/openshift/source-to-image/releases/download/v1.3.2/source-to-image-v1.3.2-78363eee-linux-amd64.tar.gz
tar -xzf source-to-image-v1.3.2-78363eee-linux-amd64.tar.gz
sudo install -m 0755 s2i /usr/local/bin/s2i
s2i version

  2. Install podman and enable the associated service.

    sudo dnf install podman
systemctl --user enable --now podman.socket
curl --unix-socket "$XDG_RUNTIME_DIR/podman/podman.sock" http://d/_ping

    The curl command above is used to check the connectivity with the podman’s socket. It should return OK for successful connection.

  3. Use the following command to fetch a project and build an OpenJDK project locally from it via the s2i toolkit:

    git clone https://github.com/alexbarbosa1989/hotrodspringboot.git

s2i --url "unix://$XDG_RUNTIME_DIR/podman/podman.sock" \
    --loglevel 5 \
    build hotrodspringboot/ \
    registry.access.redhat.com/ubi8/openjdk-17:latest \
    openjdk-hotrod:example

    The above source-to-image creation command may take a few minutes to complete. Successful run will show message like below:

    I0921 12:09:11.617074   25665 build.go:182] Build completed successfully

  4. Confirm the image was created successfully.

    podman images
    Example output:
    [lab-user@bastion ~]$ podman images
REPOSITORY                                  TAG         IMAGE ID      CREATED        SIZE
docker.io/library/openjdk-hotrod            example     cb19badb97c0  3 minutes ago  601 MB
registry.access.redhat.com/ubi8/openjdk-17  latest      abf8175bbfa5  11 days ago    411 MB
[lab-user@bastion ~]$

  5. Deploy application locally using podman

    podman run -p 8081:8080 openjdk-hotrod:example

    Success message will look like below:

    [lab-user@bastion ~]$ podman run -p 8081:8080 openjdk-hotrod:example

  6. Create a new terminal and follow the below steps in it.

  7. Check the number of CPUs available on the host machine using the nproc command:

    nproc
    Example output:
    [lab-user@bastion ~]$ nproc
2

  8. Check the running containers on the machine.

    podman ps

    Note the container ID from the output of the above command, as it will be used in the next steps.

    Example output:
    [lab-user@bastion ~]$ podman ps
CONTAINER ID  IMAGE                                     COMMAND               CREATED         STATUS         PORTS                             NAMES
d24f38a138a2  docker.io/library/openjdk-hotrod:example  /usr/local/s2i/ru...  57 seconds ago  Up 57 seconds  0.0.0.0:8081->8080/tcp, 8443/tcp  suspicious_archimedes
[lab-user@bastion ~]$

  9. Connect to the running container using the podman exec command:

    podman exec -it <container-id> /bin/bash
    Example output:
    [lab-user@bastion ~]$ podman exec -it d24f38a138a2 /bin/bash
[jboss@d24f38a138a2 ~]$

  10. List the Java processes running inside the container using the jcmd command:

    jcmd
    Example output:
    [jboss@d24f38a138a2 ~]$ jcmd
1 /deployments/hotrodspringboot-0.0.1-SNAPSHOT.jar
190 jdk.jcmd/sun.tools.jcmd.JCmd

  11. Verify the CPU limits used by the application (No CPU limits defined in the container):

    jcmd 1 VM.info | grep active_processor_count
    Example output:
    [jboss@d24f38a138a2 ~]$ jcmd 1 VM.info | grep active_processor_count
active_processor_count: 8
    The output above shows that the application is using all the CPUS available on the host machine, which an unbouded deployment and not necessarily ideal for a microservice/containerized application. To limit the CPU usage, we will now deploy the application with CPU limits.

    Exit from the container’s shell and return to the host machine’s terminal.

    exit

  12. Remove the running container and deploy it again in a container with CPU limits

    podman rm -f <container-id>

podman run -p 8081:8080 --cpus="2" openjdk-hotrod:example

  13. Follow the above steps again to connect to the running container and verify the CPU limits used by the application.

    Example output:
    [lab-user@bastion ~]$ podman ps
CONTAINER ID  IMAGE                                     COMMAND               CREATED        STATUS        PORTS                             NAMES
2f4ba2f67633  docker.io/library/openjdk-hotrod:example  /usr/local/s2i/ru...  4 minutes ago  Up 4 minutes  0.0.0.0:8081->8080/tcp, 8443/tcp  modest_kalam
[lab-user@bastion ~]$ podman exec -it 2f4ba2f67633 /bin/bash
[jboss@2f4ba2f67633 ~]$
[jboss@2f4ba2f67633 ~]$ jcmd 1 VM.info | grep active_processor_count
active_processor_count: 2
[jboss@2f4ba2f67633 ~]$
    The output above shows that the application is now using only 1 CPU, which is the limit we set for the container. This indicates that the application is container-aware therefore detects (and respects) the CPU limits set for its container.
